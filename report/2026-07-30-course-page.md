# 훈련 코스 페이지 mockup 결과 보고

- 작성일: 2026-07-30
- 산출물: `./mockup.html` (신규, 다른 페이지와 연결되지 않은 독립 목업)

## 1. 작업 개요

`tasks/course-page.md`의 지시에 따라 "Recode Coding" 훈련 코스 소개 페이지의 레이아웃 스케치를
`mockup.html` 단일 파일로 제작했습니다. 실제 서비스 페이지(`index.html` 등)와는 어떠한 링크·데이터
연결도 하지 않았으며, 상단에 "MOCKUP" 안내 배너를 고정 노출해 검토용 산출물임을 명시했습니다.

## 2. 작업 내역

| 항목 | 내용 |
| --- | --- |
| 스타일 | `index.html`과 동일한 Tailwind CDN + `brand` 컬러 + Pretendard 폰트 컨벤션을 그대로 사용해 톤을 통일 |
| 구조 | Hero → 4개 카테고리 목차 → Language / Algorithm / Web & WebApp / Unity & Unreal 4개 섹션 → 도구 검토 노트 |
| 카드 | 카테고리별로 4~5개의 예시 과정 카드(레벨 뱃지, 제목, 한 줄 설명)를 카드 형태로 제작. 카드 내용은 실제 커리큘럼이 아닌 레이아웃 검토용 예시 |
| 반응형 | 데스크톱은 카드 4~5개가 가로로 배치되고, 모바일은 카드 폭을 고정(`280px~320px`)해 자연스럽게 가로 스와이프되도록 구성 |

## 3. Swiper / GSAP 검토 결과

과제에서 요청한 "사용 여부 검토"를 위해 실제로 두 라이브러리를 목업에 적용해보고 판단했습니다.

- **Swiper — 채택 권장**: 카테고리별 카드 수가 늘어나도 모바일에서 가로 스와이프로 자연스럽게 소화되고,
  데스크톱은 섹션 제목 옆 화살표 버튼 + 하단 페이지네이션으로 탐색 가능. 카드 그리드 대비 도입 이점이
  명확해 정식 페이지에서도 사용을 권장합니다.
- **GSAP — 보류(재검토 필요)**: ScrollTrigger로 카드가 스크롤 진입 시 살짝 떠오르는 reveal 효과를
  시험 적용했습니다. 효과 자체는 자연스러우나, 현재는 레이아웃 스케치 단계이고 CSS transition만으로도
  충분히 구현 가능한 수준이라 실제 콘텐츠·인터랙션이 확정된 뒤 재검토를 권장합니다.

## 4. 중간 점검 (claude-in-chrome)

로컬 정적 서버(`python3 -m http.server`)로 `mockup.html`을 띄운 뒤 브라우저에서 확인했습니다.

- 1차 점검에서 Swiper 기본 `swiper-button-prev/next`가 카드 콘텐츠 영역과 겹쳐 첫 카드 텍스트를
  가리는 문제를 발견 → 화살표 버튼을 섹션 제목 옆(카드 영역 밖)으로 이동시키는 구조로 수정
- 데스크톱(1400px)·모바일(420px) 두 뷰포트에서 스크린샷 확인, 화살표 클릭 시 슬라이드 이동 및
  경계에서 버튼 비활성화(opacity 처리) 정상 동작 확인
- 콘솔 에러 없음 확인
- 섹션 간 여백은 `index.html`과 동일한 넉넉한 세로 리듬(`py-20`)을 따른 것으로, 별도 버그 아님을 확인

## 5. 향후 확장 계획

현재는 레이아웃 스케치 단계로 카드 데이터가 HTML에 하드코딩되어 있습니다. 콘텐츠(실제 커리큘럼 목록,
난이도 체계 등)가 확정되면 `graffiti-data.js`처럼 별도 데이터 파일로 분리하고, GSAP 적용 여부를
최종 콘텐츠 기준으로 다시 판단하는 것을 권장합니다.
