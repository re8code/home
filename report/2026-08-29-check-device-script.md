## 무엇이 문제였나 — 핑퐁 커밋

지금까지 장비를 옮길 때마다 점검 **결과**(30개 페이지 공통 요소 30/30, 내부 링크 705건, 라이브러리 버전, 경로 잔재 개수 등)를 문서와 보고서에 적어 남겼다. 이 값들은 **조회하면 알 수 있는 관측값**이라 다음 장비·다음 커밋에서 어긋나고, 그때마다 같은 줄을 고치는 커밋이 생긴다. 실제로 v0.49(경로 이동 기록)·v0.53(정합성 점검)·v0.59(장비 이동 확인)가 전부 "사이트 산출물 변경 없음"인 문서 전용 커밋이었다.

`../recodemate`의 해법은 명확하다 — **결과는 화면에만 출력하고 저장소에는 남기지 않는다. 문서에는 "결정한 것"만 두고, "조회하면 알 수 있는 것"은 스크립트가 조회한다.**

## `scripts/check-device.sh` — 이 저장소용으로 재작성

recodemate는 Next.js + Supabase + Docker 스택이라 검사 항목(Node/npm/Docker/supabase CLI/`.env.local`/lockfile/tsc/lint)이 그대로는 맞지 않는다. 뼈대(출력 형식·`ok`/`warn`/`bad`·종료 코드·드리프트 감사)만 가져오고 항목은 이 저장소 기준으로 다시 구성했다.

| 절 | 검사 |
| --- | --- |
| 도구 | `python3`·`git`·`curl`(필수), `gh`·Chrome(경고) |
| 저장소 상태 | 브랜치, **`dev`·`main` 양쪽 동기화**, 작업 트리, gitignore 대상 추적 여부(`git check-ignore --no-index`), `.DS_Store` 추적, 절대경로 하드코딩, 형제 저장소 `../business` |
| 사이트 무결성 | 페이지 수, 공통 요소 12종 전수, `md:` 잔존·인라인 `tailwind.config`, 내부 링크 전수, 섹션별 카드 연결 |
| 문서 정합성 | 문서가 가리키는 경로 실재, **CDN 버전 vs `ARCHITECTURE.md` §1 표**, GNB "준비중" vs §6, `§n` 상호참조, DEVLOG 최신 버전 |
| 경로 키 잔재 | `~/.claude.json`·`history.jsonl`의 사라진 경로, 고아 `file-history`/`session-env` — **읽기만 하고 고치지 않는다**(실행 중 편집은 종료 시 덮어써짐) |
| 문서 드리프트 | 1층 문서 diff에 관측값 패턴(`N건`, `N/30`, 버전 문자열, 용량 등)이 새로 들어왔는지 |
| 로컬 서버 | 임시 기동 후 7개 경로 200 (`--quick`으로 생략) |

옵션: `--quick`(서버 생략), `--audit`(드리프트 감사까지만 — 커밋 직전용). 포트는 `start.sh`(8765)와 겹치지 않게 8799를 쓰고 `CHECK_DEVICE_PORT`로 바꿀 수 있다.

## 작성 중 실제로 걸린 함정 2건

1. **셸 변수 뒤에 한글이 바로 붙으면 변수명으로 먹힌다.** `"origin/$b와 일치"`가 `$b와`라는 변수로 파싱돼 `set -u` 아래에서 `unbound variable`로 죽었다 → `${b}`로 감쌌다. 한글 메시지를 쓰는 셸 스크립트 전반에 해당한다.
2. **`§n` 상호참조 판정 오탐.** 처음엔 § 앞 60자 안에 문서명이 있으면 그 문서의 절로 봤는데, "`ARCHITECTURE.md` §1 기술 스택(및 §3 배포·§5 백엔드)"처럼 이어지는 참조와 "`DEV_PLAN.md` §1 … 마지막 절(§8 ADR)"처럼 다른 문서를 언급한 뒤 자기 절을 가리키는 문장에서 전부 오탐이 났다 → **같은 줄에서 앞서 언급된 문서까지 후보로 두고 그중 하나에만 존재하면 통과**로 완화하고, `docs/` 접두사가 붙은 표기(`docs/ARCHITECTURE.md`)도 인식하게 했다. 일부러 `§99`를 넣어 여전히 탐지되는 것을 확인했다.

## 문서 반영

- **`CHANGE_DEVICE.md`** — 맨 앞에 "시작 — 먼저 스크립트를 돌린다" 절 신설: 사용법 + 핑퐁 방지 원칙 + **커밋해야 하는 경우는 두 가지뿐**(프로토콜에 빠진 단계·새 함정 발견 / 스크립트가 실제 결함을 잡음). §8 마무리에서 "이동 사실을 `DEVLOG.md`에 남긴다"를 **"이동 사실 자체는 기록하지 않는다"**로 교체 — 이 문장이 핑퐁의 직접 원인이었다.
- **`CHANGE_DEVICE.md` §5 신설** (`CLAUDE.md` 새 규칙 ②) — "저장소에 없는 값". 이 저장소는 gitignore로 빠지는 설정 파일이 **없고**(`.gitignore`는 `.DS_Store` 한 줄, Firebase 설정도 추적됨 — 정적 사이트라 어차피 공개되는 값), 대신 장비마다 갖춰야 할 6가지(git 인증·python3·Chrome·gh·Firebase 콘솔 접근·닷홈 계정)를 표로 정리했다. `DEV_FALLBACK_PASSWORD`가 평문 커밋 상태라는 주의도 명시.
- **`ARCHITECTURE.md` §1** (`CLAUDE.md` 새 규칙 ①) — "운영 비용이 발생할 수 있는 지점" 표 추가. 금액·요금제 수치는 넣지 않고 **어디가 비용 지점인지**만(도메인=이미 지출 중, Pages·Firebase=무료 한도, CDN=가용성 리스크, 서브도메인=과금 개연성 1순위, LMS=미정). 조건 상세는 `ACCOUNT_COST.md`가 정본.
- **`ARCHITECTURE.md` §8 ADR D1** — "장비 점검은 스크립트가 수행하고 관측값은 저장소에 남기지 않는다"(맥락·결정·트레이드오프). ADR 절 신설 후 첫 항목.
- **`CLAUDE.md`** — 개발 명령에 스크립트 사용법 추가.
