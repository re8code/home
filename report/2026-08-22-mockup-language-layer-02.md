# mockup.html Language(2번째 레이어) 개선

## 목적
`tasks/task-layer-02.md` 반영: Language 파트를 C/C++, Java, Python, JavaScript, Dart 5개 언어로, 좌우 이동 없이 동일 크기 카드 5개가 전체 너비를 채우도록 구성.

## 수정 내용 (`mockup.html`)
`#lang` 섹션(01. Language)을 Swiper 캐러셀에서 정적 그리드로 교체.

1. **카드 구성**: 기존 Python/JS/Java/C++/Go·Rust(5장, 캐러셀) → C/C++, Java, Python, JavaScript, Dart 순서의 5장으로 교체. Go/Rust 카드는 제거, Dart/Flutter 카드를 신규 작성(설명: "선언형 UI와 상태 관리로 크로스플랫폼 데이터 흐름을 설계").
2. **좌우 이동 제거**: 섹션 헤더의 `swiper-nav-group`(이전/다음 버튼)과 `swiper`/`swiper-wrapper`/`swiper-slide` 마크업을 제거. 다른 섹션(Algorithm/Web/Unity/Agent AI)의 Swiper 캐러셀은 그대로 유지.
3. **동일 크기 · 전체 너비**: `grid grid-cols-2 sm:grid-cols-3 lg:grid-cols-5 gap-4`로 배치. 각 카드가 grid item으로 동일한 컬럼 폭/행 높이를 갖도록 함(`course-card`의 `h-full flex flex-col` 유지).

## 검증
클로드 인 크롬으로 로컬 서버(`localhost:8765/mockup.html#lang`) 확인:
- 5개 카드가 C/C++ → Java → Python → JavaScript → Dart 순서로 동일한 크기로 한 줄에 배치됨을 스크린샷으로 확인.
- 좌우 이동 화살표가 Language 섹션에만 없는 것을 확인(다른 섹션은 그대로 존재).
- 콘솔 에러 없음(`read_console_messages`, onlyErrors 필터).

## 후속: 사용자 직접 수정(뱃지 제거·라벨 전체 표기) 확인
사용자가 5개 카드에서 "입문/중급/심화" 뱃지를 직접 제거하고, 커버아트 상단 라벨을 축약형(Py/JS/Jv) → 전체 이름(Python/JavaScript/Java)으로, 카드 타이틀도 간결하게(`Python 구조 훈련`→`Python` 등) 수정. 클로드 인 크롬으로 재확인해 마크업 이상·콘솔 에러 없음 확인.

## 후속: 언어별 SVG 로고 아이콘 추가
커버아트의 텍스트 라벨을 공식 로고 스타일의 인라인 SVG 아이콘으로 교체(사용자 요청, "공식 로고 다색 재현" 방향 선택).

- 각 카드 커버아트(그린 그라디언트 배경) 안에 `h-20 w-20 rounded-2xl bg-white` 흰색 아이콘 플레이트를 추가하고, 그 안에 언어별 SVG를 배치(로고 고유 색상이 그린 배경과 섞이지 않도록).
- **C++**: 파란 육각형(#00599C, 진한 남색 오버레이) + 흰색 "C++" 텍스트.
- **Java**: 커피컵 실루엣 + 스팀 2줄, 주황~빨강 그라디언트(`#F58219`→`#E23237`).
- **Python**: 청록(#3776AB)·노랑(#FFD43B) 두 뱀 모양이 얽힌 형태 + 흰색 눈 점, 공식 로고를 단순화해 재현.
- **JavaScript**: 공식 브랜드 컬러(#F0DB4F) 정사각형 + 검정 "JS" 텍스트.
- **Dart**: 파란 계열 4가지 톤(#00589C/#0175C2/#13B9FD/#40C4FF)의 삼각 facet로 구성한 다이아몬드형 로고. 1차 시안은 폭이 너무 얇아 존재감이 약해, 캔버스를 넓게 쓰는 kite 형태로 좌표를 재조정하고 아이콘 크기도 `h-12`→`h-14`로 확대.
- 클로드 인 크롬으로 5개 아이콘 전체 스크린샷 확인 + Dart 아이콘 확대(zoom)로 형태 검수, 콘솔 에러 없음.

## 후속: 손그림 SVG → 실제 공식 로고 PNG로 교체
사용자 판단으로 손으로 그린 근사 SVG 대신, 웹에 이미 잘 정리된 공식 로고 리소스를 찾아 다운로드해 사용하기로 방향 전환.

1. **1차 다운로드** (`assets/image/`): C++/Java/Python/JavaScript는 GitHub `abranhe/programming-languages-logos`(npm 패키지, MIT 라이선스) 512×512 PNG, Dart는 Wikimedia Commons `Dart_logo.png`(Google 공식 자산, dart.dev/brand 출처, CC BY 4.0, 1080×1080). 아이콘 단독(텍스트 없음) 버전.
2. **2차 교체(워드마크)**: 사용자가 Java/Python/Dart는 "언어명이 함께 구성된 로고"를 요청 — devicon(MIT 라이선스) 저장소의 `*-original-wordmark.svg` 3종(아이콘+텍스트 결합형)을 찾아 확정. 로컬에 SVG→PNG 변환 도구(rsvg-convert/cairosvg/imagemagick 등)가 없어 공개 이미지 프록시(wsrv.nl)로 래스터화(`&w=1000&output=png`). Java/Python은 정상 변환됐으나, `&trim=1` 옵션이 Java 렌더링에서 배경을 검게 깨뜨리는 부작용이 있어 두 파일은 trim 없이 재렌더링. Dart는 원본 SVG 캔버스가 정사각형이라 여백이 커 `trim=1`로 투명 여백만 잘라 가로형(1000×266)으로 정리. Pillow로 코너 픽셀 alpha 값을 확인해 3개 파일 모두 투명 배경(alpha=0)임을 검증 후 `assets/image/java.png`/`python.png`/`dart.png`를 덮어씀. C++/JavaScript는 아이콘 자체에 이미 텍스트가 포함돼 있어 1차 아이콘 단독 버전을 그대로 유지.
3. **mockup.html 반영**: 각 카드 커버아트의 SVG 인라인 아이콘을 `<img src="assets/image/{lang}.png">`로 교체. 흰색 플레이트를 `h-20 w-20` 고정 정사각형 대신 `px-5 py-4`(Dart는 `px-6 py-4`) 패딩 기반으로 바꿔, 이미지별 원본 비율(정사각 아이콘 vs 세로형 워드마크 vs 가로형 Dart 배너)에 맞게 플레이트 너비가 자동으로 맞춰지도록 함. 이미지 높이는 `cpp`/`javascript` h-14, `java`/`python` h-20, `dart` h-9로 각각 시각적 균형에 맞게 개별 지정.
4. 클로드 인 크롬으로 로컬 서버 재확인: 5개 카드 모두 실제 로고 렌더링 정상, 콘솔 에러 없음.

## 후속: 흰색 플레이트 제거 + 이미지 확대
사용자 요청("배경인 녹색과 어울어지게 투명 처리, 이미지 크기 확대")에 따라 흰색 `bg-white` 플레이트(`px-5/6 py-4 rounded-2xl shadow-lg`)를 제거하고 `<img>`를 그린 그라디언트 커버아트 위에 직접 배치, `drop-shadow-lg`만 남겨 배경과 잘 어울리면서도 형태가 뜨도록 처리. 5개 파일 모두 코너 픽셀 alpha=0(cpp/java/python/dart) 또는 둥근 모서리 안티앨리어싱(javascript, alpha≈193)으로 투명 배경이 확인되어 별도 편집 없이 바로 사용 가능했음.

이미지 높이도 상향: `cpp`/`javascript` h-14→h-24, `java`/`python` h-20→h-28, `dart` h-9→h-14. 클로드 인 크롬으로 재확인, Dart 카드는 확대(zoom)해 텍스트 가독성도 점검(그라디언트 어두운 구간에서도 drop-shadow 덕분에 판독 가능). 콘솔 에러 없음.

## 후속: 배경 그린 그라디언트를 밝은 톤으로 재설정
흰색 플레이트를 없앤 뒤에도 로고가 잘 안 보인다는 피드백 — 원인은 커버아트 그라디언트가 `--from:#74e4ad`(brand-300)에서 `--to:#0d5d42`(brand-800, 매우 어두운 그린)로 떨어져, 어두운 우하단 구간에서 Dart의 짙은 회색 텍스트·C++ 남색 등 어두운 색상 로고 요소가 묻히는 것이었음.

Language 5개 카드의 `--from`/`--to`를 브랜드 팔레트 안에서 더 밝은 조합인 `--from:#d5f9e4`(brand-100) → `--to:#3ecf8e`(brand-400)로 교체(다른 카테고리 섹션의 teal/sky/amber/violet 그라디언트는 영향 없음). 클로드 인 크롬으로 재확인: 전체적으로 카드가 밝아지고 5개 로고 모두 배경과 뚜렷하게 구분됨, 콘솔 에러 없음.

## 후속: 언어별 특징·학습적 의미를 반영한 소개 문구 개편
5개 카드 설명 문구가 서로 비슷한 톤("데이터 흐름 관점" 반복)이라 언어별 차별점이 잘 안 드러난다는 지적 → 각 언어의 고유 특성과 "왜 이 언어를 배우는가"라는 학습 의미를 살려 재작성.

- **C/C++**: "메모리·포인터 관점에서 데이터 흐름의 물리적 실체를 이해" → "메모리를 직접 다루며 컴퓨터가 동작하는 물리적 원리를 체득" — 가비지 컬렉터 없이 메모리를 직접 관리하는 유일한 저수준 언어라는 특징 강조.
- **Java**: "객체·타입 설계를 통한 구조적 사고 훈련" → "엄격한 타입 체계와 객체지향 설계로 대규모 시스템의 구조적 사고를 훈련" — 강타입·OOP로 대규모 시스템을 설계하는 기업/코딩테스트 표준 언어라는 맥락 보강.
- **Python**: "문법이 아닌 자료형·흐름 제어의 데이터 흐름 관점으로 접근" → "쉬운 문법 덕분에 로직 자체에 집중하며, AI 시대 표준 언어로 확장되는 사고 훈련" — 낮은 문법 장벽과 AI/데이터 분야 표준어라는 시의성 반영.
- **JavaScript**: "비동기·타입 시스템을 통해 데이터 흐름을 명시적으로 설계" → "브라우저에서 실행되는 유일한 언어로, 비동기 이벤트 흐름을 다루는 사고 훈련" — 브라우저 네이티브 언어라는 유일성과 비동기/이벤트 기반 사고모델 강조.
- **Dart**: "선언형 UI와 상태 관리로 크로스플랫폼 데이터 흐름을 설계" → "선언형 UI 문법으로 하나의 코드가 여러 플랫폼에 반영되는 흐름을 설계" — Flutter 기반 하나의 코드베이스, 여러 플랫폼 배포 특징을 더 구체화.

클로드 인 크롬으로 재확인: 5개 카드 모두 2줄 내외로 자연스럽게 줄바꿈, 콘솔 에러 없음.
