## 요약

**무엇을** — 대문 재편(D6)의 실행 방식을 뒤집었다. 기존: `student` 신규 → 24장 이관 → `home` 축소. 새: **이 저장소가 `student`가 되고 대문을 새 저장소로 뺀다.**

**왜** — 파일을 실제로 나눠 보니 대문으로 남는 것이 시안 1장과 정본 몇 개뿐이었다. 지금의 `index.html`도 5개 코스 섹션의 학습 허브라 `student`의 첫 화면감이다. 움직이는 양이 적은 쪽을 옮기면 24장·문서·점검 스크립트·`report/`의 이력이 그대로 이어지고, 학습 콘텐츠가 처음부터 `student` 주소에 살아 있어 "빈 집" 문제가 사라진다.

**낙서장** — 원장의 목소리 = 에이전시의 목소리, 학생·기업 양쪽이 읽는 자리, 대문 GNB(v0.103)에 이미 있음 → 새 대문으로. D6의 "student 원장 칼럼 유력"을 뒤집었다. 같은 도메인이라 Firebase Auth 허용 도메인 변경 없음. Firestore → Supabase 전환은 저장소 이전과 겹치지 않게 나중에 별도 판단.

**`mission`** — 훈련생~에이전트 프로젝트 관리 시스템(회의록 `_handoff/`). `agency`(사다리 허브 저장소를 시스템으로 전환), `hq`와 비교 후 `mission` — 007 은유(프로젝트 = 임무), 다른 저장소와 겹치지 않아 바로 쓸 수 있음. 주소 체계: 대문 · `student`(배우는 곳) · `mission`(일하는 곳) · `business`.

**GitHub 조직** — 회사용 개인 계정을 따로 여는 안과 비교. 조직은 개인 계정으로 관리(공용 로그인 없음), 소유자 복수 가능, 팀·CODEOWNERS 팀 지정, GitHub App 설치 대상 — `mission`의 요구(저장소 자동 생성·문서별 권한·훈련생 초대/회수)가 전부 조직 기능. 새 저장소부터 조직에, 기존 저장소는 천천히 이전.
