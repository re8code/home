# 2026-09-10 — GNB 순서 변경 + 1:1 상담 폼 이관 방향

GNB에서 `studio`를 옮기고 배포했다. 그리고 **1:1 상담 폼을 Firebase로 옮길지**를 논의해 방향만 정했다 — 폼 자체는 아직 손대지 않았다.

## 체크리스트

- [x] GNB `studio`를 `wonoj` 오른쪽으로 이동 (v0.92) — 정본 1곳 수정 후 빌드, 30장 확인
- [x] `main` 병합·배포 (v0.90 → v0.92), 라이브 반영 확인
- [x] 1:1 상담 폼의 Firebase 이관 검토 — **보류 결정**
- [x] 대안(소유권 이전) 절차 정리
- [x] 폼 URL이 저장소 29곳에 박혀 있음을 실측

## 1. GNB 순서

`원장님의 낙서 → wonoj → studio → LMS(준비중) → business`.

`partials/header.html` 한 곳(데스크톱 nav·모바일 메뉴 두 블록)만 고치고 빌드했다. 30장 전부 같은 순서인지 파싱으로 확인. **ADR D3 이전이었다면 30장 60곳 일괄 치환이었을 작업**이다.

## 2. 1:1 상담을 Firestore로 옮기는 안 — 보류

사용자 질문: *"Google form을 현재 사용되고 있는 firebase 쪽으로 돌리는 건 어떻게 생각해?"*

**얻는 것은 UX가 아니라 계정 정리다.** `ACCOUNT_COST.md` §4의 "이 계정을 정리할 때 양식을 함께 옮기지 않으면 상담 접수가 끊긴다"가 통째로 사라지고, `triwon20@gmail.com`을 닫을 수 있게 된다.

**그런데 대가가 셋이다.**

| 대가 | 내용 |
| --- | --- |
| **스팸** | 폼 쓰기를 공개하면 `create`를 열어야 하는데 **규칙으로는 레이트 리밋을 걸 수 없다.** 봇이 밀어넣으면 Spark 한도가 소진돼 **낙서장까지 함께 멈춘다** — 지금은 쓰기가 계정 하나로 잠겨 있어 이 위험이 아예 없다 |
| **알림 소실** | Forms는 응답 시 메일이 온다. Firestore는 아무 일도 일어나지 않아 콘솔을 직접 열어야 한다. 메일 알림에는 Cloud Functions가 필요하고 그것은 **Blaze 전환 = 과금 시작**이다. 상담 신청을 놓치는 것은 실제 매출 손실이라 이게 가장 크다 |
| **개인정보** | 이름·연락처를 무료 티어에 직접 쌓게 된다. Google이 지던 책임을 이쪽이 진다 |

**결론 — 지금 규모(하루 몇 건)에서는 Forms가 더 안전하고 손이 덜 간다.** 옮길 조건은 둘 중 하나가 생겼을 때다: ① 다른 이유로 Blaze에 올라가 알림 문제가 해소되거나, ② 유입이 늘어 폼 이탈률이 실제로 아까워지거나.

## 3. 대신 할 것 — 소유권만 이전

**얻으려던 것(계정 정리)의 대부분을 대가 없이 가져간다.** Drive 파일 소유권 이전이라 Firebase와 무관한 절차다.

### Path A — 소유권 이전 (URL 유지, 응답 보존)

게시 URL `/forms/d/e/1FAIpQLSe…/viewform`은 **폼 ID 기반이라 소유자가 바뀌어도 그대로다.** 저장소는 한 줄도 안 건드린다.

1. `triwon20@gmail.com`으로 Drive 접속 → 폼 우클릭 → **공유**
2. `won@re8code.com`을 **편집자**로 추가
3. 다시 공유 창 → 그 계정 드롭다운 → **"소유자로 지정"**
4. `won@re8code.com`으로 로그인해 **수락**
5. **응답 스프레드시트도 별개 파일이다** — 연결돼 있으면 같은 절차를 반복

**3번이 막힐 수 있다.** `triwon20@gmail.com`은 개인 계정, `won@re8code.com`은 `re8code.com` 조직 계정이라 Google이 조직 경계를 넘는 이전을 제한하는 경우가 있다("소유자로 지정"이 안 보이거나 회색). **확인은 사용자만 할 수 있다** — 2번(편집자 공유)까지만 돼도 실무 관리에는 지장이 없다.

### Path B — 복사 (3번이 막혔을 때)

**URL이 바뀌고 기존 응답이 따라오지 않는다.** 새 폼을 만들고 URL을 받아 저장소 29곳을 교체한다. 옛 폼은 **삭제하지 말고 응답 받기만 끈다**(외부에 뿌려진 옛 링크 때문).

## 4. 실측 — 폼 URL이 정본 밖 27곳에 있다

이번에 처음 드러났다.

| 위치 | 개수 | 고치는 법 |
| --- | --- | --- |
| `partials/header.html` (GNB CTA 데스크톱·모바일) | 2 | 정본 1곳 → 빌드 |
| **각 페이지 하단 CTA 섹션 (마커 밖)** | **27** | **손으로 27장** |

하단 CTA는 페이지마다 카피가 달라("지금, 1:1 상담으로 시작하세요" / "자료구조도 손으로 직접 다뤄봐야…") 정본화 대상이 아니었다. 링크만 같고 문구가 다르다.

**그래서 Path A(URL 유지)가 Path B보다 이 저장소에는 훨씬 싸다.** 외부에 이미 뿌려진 링크까지 고려하면 차이는 더 벌어진다.

## 남은 이슈

- **Path A 3번이 되는지는 사용자만 확인할 수 있다.** 결과에 따라 B로 갈지 갈린다.
- 이전이 끝나면 `ACCOUNT_COST.md` §2·§4에서 "Forms는 여전히 `triwon20` 소유" 서술을 걷어낸다 — **그 계정을 닫을 수 있게 되는 시점**이다.
- 하단 CTA 27곳은 링크가 같고 문구만 다르다. 정본화한다면 "링크는 정본, 문구는 페이지"로 쪼개는 설계가 필요한데, 지금 이득이 URL 교체 한 번뿐이라 착수하지 않았다.
