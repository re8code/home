# Algorithm 코스 시각화 콘텐츠 리스트업 보고서

- 작성일: 2026-08-22
- 작업 대상: Algorithm 코스 기획 (visualgo.net 벤치마크 + 시각화 대상 알고리즘 리스트업)
- 성격: 구현 이전 단계의 기획 문서 — 이 문서 자체는 코드 변경을 포함하지 않음

## 1. 배경

Language 코스(`lang-cp.html` 등 5개 페이지)에 이어 Algorithm 코스도 동일한 수준으로 다뤄보고 싶다는 요청에서 출발했다.

1. 먼저 Language와 같은 12주 커리큘럼 포맷(기초 5 · 실습 5 · 프로젝트 2)으로 Algorithm 코스 초안을 대화 중 제안함.
2. 이어서 "visualgo.net 형태로 알고리즘을 시각적으로 보여주는 형태로 제작할 수 있나?"라는 질문을 받음 — 현재 스택(빌드 도구 없는 정적 HTML + Tailwind CDN + Vanilla JS)만으로 SVG/Canvas 기반 애니메이션 구현이 기술적으로 가능하다고 답했고, 다만 알고리즘 하나당 "상태 기록 + play/pause/step 컨트롤 + 렌더링"을 만들어야 해서 작업량이 크므로 파일럿 2~3개부터 시작할 것을 제안함.
3. 사용자가 이에 동의하며, 파일럿 후보를 고르기 위한 전체 알고리즘 리스트업과 이 보고서를 먼저 요청함.

## 2. visualgo.net 벤치마크

`https://visualgo.net`을 직접 확인한 결과, 총 24개 시각화 모듈을 4단계 난이도로 구성하고 있다(싱가포르국립대 CS1010~CS4234 커리큘럼 기준이라 대학 전공 수준까지 포괄하는 매우 방대한 사이트임).

- **기본 자료구조**: Array, Sorting, Linked List(스택/큐/이중연결리스트 포함), Binary Heap, Hash Table
- **고급 자료구조**: Binary Search Tree(AVL 포함), Graph Structures, Union-Find, Fenwick Tree, Segment Tree, Bitmask
- **그래프 알고리즘**: Graph Traversal(DFS/BFS/이분그래프/SCC), MST(Prim/Kruskal), 단일출발 최단경로(Dijkstra/Bellman-Ford), Cycle Finding, Network Flow, Graph Matching, Min Vertex Cover
- **고급 알고리즘**: 재귀트리/DAG(DP), Suffix Tree/Array, Convex Hull, Geometry, NP-complete 문제(Steiner Tree/TSP 등)

Recode Coding의 Algorithm 코스는 "코딩테스트 대비 + 구조적 사고 훈련"이 목적이라, 위 24개 전부를 따라갈 필요는 없다. 아래 3절은 이 중 학생 학습 관점에서 실제로 다룰 만한 항목만 선별해 정리한 것이다.

## 3. Algorithm 코스 리스트업 (학생 학습 관점)

앞서 대화에서 제안한 12주 커리큘럼(기초 5 · 실습 5 · 프로젝트 2)에 대응시켜, 각 항목마다 "왜 배우는가"와 "어떻게 시각화할 수 있는가", 구현 난이도를 함께 정리했다.

### 3-1. 기초 — 자료구조 (1~5주 대응)

| # | 항목 | 학습 포인트 | 시각화 아이디어 | 구현 난이도 |
|---|---|---|---|---|
| 1 | 배열·문자열 (투 포인터/슬라이딩 윈도우) | 가장 기본적인 자료구조, 이후 모든 기법의 재료 | 배열 칸을 사각형으로, 두 포인터가 화살표로 이동 | 쉬움 |
| 2 | 스택·큐 | LIFO/FIFO, 괄호 매칭·BFS의 전제조건 | push/pop·enqueue/dequeue 시 쌓이고 빠지는 애니메이션 | 쉬움 |
| 3 | 재귀와 백트래킹 | 문제를 더 작은 동일 문제로 쪼개는 관점 | 호출 스택을 트리로 그리며 depth마다 색상 변화 | 보통 |
| 4 | 연결리스트와 이진트리 | 포인터 기반 구조, 트리 순회(전위/중위/후위) | 노드-화살표 다이어그램, 순회 경로를 순서대로 하이라이트 | 보통 |
| 5 | 힙(Heap) | 우선순위 큐, heapify 과정 | 배열과 트리를 동시에 보여주며 sift-up/down 애니메이션 | 보통 |

### 3-2. 실습 — 알고리즘 패러다임 (6~10주 대응)

| # | 항목 | 학습 포인트 | 시각화 아이디어 | 구현 난이도 |
|---|---|---|---|---|
| 6 | 정렬 (버블/선택/삽입/병합/퀵) | 같은 문제, 다른 시간복잡도를 체감 | 막대그래프 높이 비교 + 스왑/분할 애니메이션 — **시각화 효과가 가장 크고, 5개 알고리즘이 하나의 "막대그래프 엔진"을 공유 가능** | 쉬움~보통 |
| 7 | 이진 탐색 | 정렬된 데이터에서 로그 시간 탐색 감각 | 탐색 범위(mid 기준 좌우)가 좁아지는 과정을 색으로 표시 | 쉬움 |
| 8 | 그래프 탐색 (BFS/DFS) | 그래프 표현법, 최단경로의 기초 | 노드를 방문 순서대로 색칠, 옆에 큐/스택 상태를 함께 표시 — **교육 효과가 매우 크고 난이도는 중간** | 보통 |
| 9 | 그리디 알고리즘 | 지역 최적해 ≠ 전역 최적해인 경계 이해 | 활동 선택 문제 등에서 매 단계 선택되는 항목을 강조 | 쉬움 |
| 10 | 동적 계획법 (DP) | 부분 문제 분해 + 메모이제이션 — 학생들이 가장 어려워하는 구간 | DP 테이블이 한 칸씩 채워지는 애니메이션(피보나치/배낭문제/LCS) — **개념 이해 임팩트는 최대지만 문제마다 테이블 형태가 달라 구현 손이 많이 감** | 보통~어려움 |

### 3-3. 프로젝트 (11~12주 대응)

| # | 항목 | 학습 포인트 | 비고 |
|---|---|---|---|
| 11 | 코딩테스트 실전 전략 | 시간복잡도로 접근법을 역산하는 훈련 | 별도 시각화보다는 문제 유형별 풀이 전략 정리에 가까움 |
| 12 | 미니 프로젝트 — 알고리즘 시각화 도구 직접 제작 | 배운 알고리즘을 "구현"이 아니라 "설명 가능"한 수준으로 끌어올림 | 학생이 스스로 1~10주차에서 다룬 알고리즘 중 하나를 골라 시각화 앱을 만들어보는 실습으로 설계 가능 |

## 4. 파일럿 우선순위 제안

전부를 한 번에 만들기보다, **시각화 효과가 크면서 구현 난이도가 낮은 항목부터** 시작하는 것을 제안한다.

1. **정렬 알고리즘 5종** (버블/선택/삽입/병합/퀵) — 막대그래프라는 하나의 시각화 엔진을 재사용해 5개 알고리즘을 동시에 커버할 수 있어 투입 대비 산출이 가장 크다. visualgo에서도 가장 상징적인 콘텐츠.
2. **그래프 탐색 (BFS/DFS)** — 노드-엣지 다이어그램 + 방문 순서 색칠은 학생 이해도 향상 효과가 크고, 구현 난이도는 정렬보다 한 단계 위이지만 여전히 감당 가능한 수준.
3. **이진 탐색** — 구현이 가장 단순해 위 두 엔진(막대그래프/그래프 다이어그램) 사이에 낀 시간에 빠르게 추가 가능한 항목.

이 3개 카테고리로 정렬 5종 + BFS/DFS 2종 + 이진 탐색 1종, 총 8개 알고리즘을 3개의 시각화 엔진(막대그래프 / 노드-엣지 / 범위 하이라이트)만으로 커버할 수 있다.

DP는 학생들이 가장 어려워하는 만큼 시각화 임팩트도 가장 크지만, 문제마다 테이블 형태가 달라 재사용 가능한 단일 엔진을 만들기 어렵다 — 파일럿 이후, 위 3개 엔진의 완성도와 사용자 반응을 먼저 확인한 뒤 별도로 착수하는 것을 권장한다.

## 5. 다음 단계 (제안, 미착수)

- 사용자 확인 후, 파일럿 3종(정렬 5개 / BFS·DFS / 이진 탐색)부터 SVG + Vanilla JS로 구현 착수.
- 공통 설계: "상태 스냅샷 배열 기록 → play/pause/step/reset 컨트롤이 스냅샷 인덱스만 이동" 패턴으로 시각화 엔진을 알고리즘 로직과 분리해두면, 이후 다른 알고리즘 추가 시 컨트롤 UI를 재사용할 수 있음.
- 페이지 구조는 Language처럼 언어별로 나눌 필요가 없으므로(Algorithm은 언어에 종속되지 않음), 단일 `algo.html` 안에 12주 커리큘럼 카드(아코디언, `lang-cp.html`과 동일 패턴) + 시각화가 준비된 항목만 "시각화 보기" 링크/버튼을 추가하는 방식을 제안.
