# 2026-08-30 — 공통 마크업 정본화(ADR D3) — 푸터 · GNB · head

푸터 리디자인을 논의하다 "매번 30장을 수정하는 것이 바람직한가"라는 물음이 나와, 디자인보다 **구조를 먼저** 정리했다. 사용자가 B안(빌드 스크립트 + 산출물 커밋)을 선택.

## 1. 결정의 근거 — 측정값

말이 아니라 숫자로 확인한 것들.

| 확인 | 값 |
| --- | --- |
| `DEVLOG`의 "30개 페이지 일괄 치환" | **16회** |
| 커리큘럼형 페이지 중 정형부 비율 | `lang-dt` 172/426줄 = **40%** (head 43 + header 65 + footer 43) |
| 시각화 페이지 | `algo-bst` 168/642줄 = 26% (본문이 큰 만큼 비율은 낮음) |

| `check-device.sh`가 30/30으로 검사하는 공통 요소 | **12개** — 드리프트를 *사후에* 잡기 위한 검사 |

**드리프트는 이론이 아니라 이미 일어난 일이었다** — 푸터가 3종으로 갈라졌고, `graffiti*` 3장은 GNB에서 2026-08-26 폐기한 `R/` 텍스트 배지를 아직 달고 있었다. 지금까지 터진 공통부 버그(모바일 메뉴 미개방, 폴드7 GNB 줄바꿈, "회사 소개" 상시 흰색)도 전부 이 복제 영역에서 났다.

## 2. 채택하지 않은 안

| | 이유 |
| --- | --- |
| 런타임 JS 주입(`footer.js`) | 크롤링에 안 잡히고, FOUC 방지(critical CSS로 어렵게 잡아둔 것)를 잃는다. GNB에는 아예 못 쓴다 |
| SSG(Eleventy 등) | `package.json`·npm 도입 — 명시적으로 배제한 것. Pages 브랜치 배포가 `/`·`/docs`만 지원해 Actions 배포로 갈아타야 한다 |

**배포는 아무것도 나아지지 않는다 — 그게 B를 고른 이유다.** 생성 결과를 커밋하므로 Pages가 받는 파일은 종전과 동일한 정적 HTML이고, 배포 경로·`CNAME`·`main` 푸시 흐름이 전혀 바뀌지 않는다.

## 3. 만든 것

**`partials/footer.html`** — 푸터 정본. 페이지별로 달라지는 경로는 토큰으로 둔다.

| 토큰 | 루트(`index.html`) | `src/` 페이지 |
| --- | --- | --- |
| `{{HOME}}` | `""` | `../index.html` |
| `{{SRC}}` | `src/` | `""` |
| `{{ASSET}}` | `assets/` | `../assets/` |

**`scripts/build-partials.py`** — 마커(`<!-- @partial:footer -->` … `<!-- /@partial:footer -->`) 사이를 정본으로 채운다. `--check`는 파일을 고치지 않고 어긋난 페이지가 있으면 종료코드 1. 여는 마커의 들여쓰기까지 잡아 블록을 통째로 다시 쓰므로 마커가 비어 있어도 물리고 재실행이 멱등이다. 치환되지 않은 토큰이 남으면 오류로 멈춘다.

**`check-device.sh` "공통 마크업" 항목** — 매 점검 때 `--check`를 돌려 정본과 생성물을 대조한다. ADR D3이 감수한 유일한 위험(마커 안을 직접 고치면 덮어써짐)을 구조적으로 막는 장치다.

| 브라우저 렌더링 | 헤드리스 Chrome DOM 덤프 4개 페이지 — 칼럼 4개·링크 11개·`RECODE` 정상, 루트는 `#lang`·`src/about.html`, `src/`는 `../index.html#lang`·`about.html`로 정확히 갈림 |
| 스크린샷 | `src/graffiti.html`이 표준 푸터로 통일된 것 육안 확인 |

### 의도적으로 달라진 4장

- `index.html` — 리소스 칼럼의 죽은 "블로그"(`href="#"`)가 다수안(26장)과 같은 **"원장님의 낙서"(실제 링크)** 로 바뀜.
- `graffiti.html` · `graffiti-detail.html` · `graffiti-new.html` — 링크가 하나도 없던 옛 미니 푸터(폐기된 `R/` 배지 포함)가 **표준 푸터로 통일**됨.

### 잡은 버그 1건

초기 구현에서 `{{HOME}}`을 `src/` 페이지에 `index.html`로 넣어 **`src/index.html`(존재하지 않음)을 가리키는** 링크가 30장에 생길 뻔했다. 커밋 전 "이전 커밋과 푸터 링크 대조" 검사에서 즉시 드러나 `../index.html`로 수정. 리팩터링은 렌더링이 동일해야 한다는 전제를 검사로 세워둔 것이 값을 했다.

## 5. 같은 날 확장 — GNB와 `<head>`도 정본화 (v0.66)

푸터로 방식이 검증되자 사용자 지시로 나머지 두 덩어리도 정본화했다. **정본 3종**이 됐다.

| 정본 | 담은 것 | 토큰 |
| --- | --- | --- |
| `partials/header.html` | GNB 전체(로고·nav·CTA·모바일 메뉴) | `{{HOME_HREF}}` `{{ASSET}}` `{{SRC}}` |
| `partials/head-common.html` | OG 9종 · favicon · `base.css` · Tailwind CDN · config · Pretendard | `{{URL}}` `{{TITLE}}` `{{DESC}}` `{{ASSET}}` |
| `partials/footer.html` | 푸터 전체 | `{{HOME}}` `{{SRC}}` |

페이지에 남는 것은 `<title>` · `<meta name="description">` · 페이지 고유 `<style>` · 페이지 전용 CDN(`index.html`의 Swiper/AOS)뿐이다.

### OG 태그 이중 관리 제거

종전에는 `CLAUDE.md`에 이런 주의사항이 있었다 — *"`og:title`/`og:description`은 각 페이지의 `<title>`/`<meta description>`을 그대로 재사용하므로 문구를 고칠 때 OG 태그도 함께 갱신해야 함을 유의"*. 사람이 기억해야 하는 규칙이었다.

`{{TITLE}}`·`{{DESC}}`·`{{URL}}`을 페이지의 `<title>`·`description`·파일 경로에서 **파생**시켜 이 규칙을 없앴다. 대체하기 전에 **30장 전수 확인으로 og:title/description/url이 이미 title·description·경로와 30/30 일치**함을 먼저 검증해, 파생으로 바꿔도 값이 달라지지 않음을 보장했다.

`<title>` 원문은 이미 HTML 이스케이프된 상태이므로 **그대로 복사**하고 속성을 깨뜨리는 따옴표만 `&quot;`로 바꾼다 — 여기서 `&`를 다시 이스케이프하면 나중에 `Web &amp; WebApp` 같은 제목에서 `&amp;amp;`가 된다. 제목에 `&`를 넣어 실제로 확인했다(이중 이스케이프 0건).

### GNB 전용 토큰

로고 링크가 루트에서는 `href="#"`, `src/`에서는 `href="../index.html"`로 **형태 자체가 달라** `{{HOME}}`(앵커 접두사용)으로는 표현되지 않았다. `{{HOME_HREF}}`를 따로 뒀다.

| OG 파생 실증 | `<title>`을 바꾸고 빌드하니 `og:title`이 따라 바뀜 |

## 남은 이슈

- **푸터 디자인은 아직 미결.** 이번 작업은 순수 구조 전환이라 내용은 기존 4단형 그대로다. 목업 4안(다크 대비 / 라이트 정돈 / CTA 결합 / 미니멀) 중 고르면 이제 **`partials/footer.html` 한 파일만 고치면** 30장에 반영된다.
- 죽은 링크 2개(FAQ·문의 `href="#"`)는 그대로 남겨뒀다 — 목적지가 정해지지 않아 구조 전환과 함께 임의로 바꾸지 않았다.
- 정본은 3종(`header`·`head-common`·`footer`)이다. 남은 후보는 **코스 바로가기 탭** — `lang-*` 5장과 `web-*` 5장이 서로의 링크를 들고 있어 "새 페이지 1장 = 파일 6장 수정"이고, 페이지가 늘수록 비용이 커지는 유일한 항목이다. 다만 탭은 현재 페이지에 `aria-current="page"`와 `is-active`가 붙어 페이지마다 마크업이 실제로 달라지므로, 경로 토큰만으로는 부족하고 "현재 페이지" 개념을 빌드 스크립트에 추가해야 한다.
