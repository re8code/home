## 1. C/C++ 출력 항목에서 C++ 스트림 제거

직전 작업(v0.57)에서 1번 카드를 "printf와 std::cout"으로 만들어 두 언어의 출력 방식을 나란히 비교하게 했으나, 지시에 따라 **C++ 스트림 내용을 전부 걷어내고 C의 `printf` 계열만** 남겼다.

| | 변경 전 | 변경 후 |
| --- | --- | --- |
| 제목 | 출력(Output) — printf와 std::cout | **출력(Output)** |
| 요약 | …C의 printf 서식 지정자와 C++의 std::cout 스트림을 나란히 비교합니다 | 화면에 값을 출력하는 것부터 시작합니다. printf의 서식 지정자와 줄바꿈·버퍼 처리를 다룹니다 |
| 상세 | printf 서식 지정자 / **std::cout `<<`** / `\n` vs **std::endl** / stderr | printf 서식 지정자 / **puts와의 차이** / `\n`과 **fflush** / **fprintf로 stderr 분리** |

C++ 문법은 기존대로 9~11번 카드(C++ 객체지향 기초 · STL과 표준 컨테이너 · 스마트 포인터와 RAII)에서 다루므로 커리큘럼 전체에서 빠지는 내용은 없다. `lang-cp.html`에 `std::cout` 문자열 잔존 0건 확인.

**정보 손실이 없음을 확인했다** — 부제가 담던 구체적 내용은 바로 아래 항상 보이는 요약 `<p>`가 이미 갖고 있다. 예: `web-backend`의 12번은 제목이 "미니 프로젝트"만 남지만 요약이 "인증·DB 연동을 포함한 API 서버를 처음부터 설계하고 구현합니다"로 무엇을 만드는지 그대로 알려준다.

정규식으로 제목 `<p>` 안의 `… — …` 패턴만 좁혀 치환했고(요약·상세 문장 안의 대시는 건드리지 않음), 치환 후 제목 내 `—` 잔존 0건을 확인했다.

## 3. 아이템 hover(포커스) 효과 제거

커리큘럼 페이지 **11개**(`lang-*` 5, `web-*` 5, 미사용 `algo-sort.html` 1)에서 아래 두 CSS 규칙을 삭제했다.

```css
.curriculum-card { transition: transform .2s ease, border-color .2s ease, box-shadow .2s ease; }
.curriculum-card:hover {
  transform: translateY(-2px);
  border-color: rgba(24, 180, 118, 0.4);
  box-shadow: 0 16px 32px -18px rgba(15, 23, 42, 0.2);
}
```

`transition`도 함께 지웠다 — hover 규칙이 사라지면 전이시킬 상태 변화가 남지 않기 때문이다. **카드의 동작 자체는 그대로다**: `cursor-pointer`, 클릭/키보드 토글, 셰브런 회전, 아코디언 펼침·접힘, 포커스를 잃으면 자동으로 접히는 동작 모두 유지된다. 없앤 것은 마우스를 올렸을 때 카드가 떠오르고 테두리가 초록으로 바뀌던 시각적 강조뿐이다.

## 남은 이슈

- `web-*` 5개 페이지의 1번 카드 제목이 부제 제거로 **"1. OT" 한 단어만** 남았다. 요약 `<p>`가 내용을 설명하고는 있지만, 다른 항목들이 "HTML/CSS 구조화"처럼 주제를 드러내는 명사구인 것과 비교하면 유독 정보량이 적다. Language 페이지처럼 1번을 구체적 주제로 바꿀지는 사용자 판단이 필요하다.
- v0.57에서 언급한 "제거된 OT 내용(언어별 실행 모델) 복원 여부"는 여전히 미결.
