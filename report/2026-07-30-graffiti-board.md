# "원장님의 낙서" 게시판 추가 결과 보고

- 작성일: 2026-07-30
- 산출물: `./graffiti.html`, `./graffiti-detail.html`, `./assets/js/graffiti-data.js`, `./index.html`(네비게이션 수정)

## 1. 작업 개요

`task.md`의 지시에 따라 홈페이지에 "원장님의 낙서" 게시판을 추가했습니다.
`https://korea-pass.kr/notice/noticeList.do` / `noticeDetail.do` 페이지를 claude-in-chrome으로
직접 열어 목록·상세 레이아웃(브레드크럼, 검색창, 카드형 리스트, 상세 메타 정보, 이전글/다음글 영역,
목록 버튼)을 벤치마크한 뒤, `index.html`의 다크 테마·브랜드 컬러 톤에 맞게 재구성했습니다.

## 2. 작업 내역

| 항목 | 내용 |
| --- | --- |
| 네비게이션 | `index.html` 상단 네비 우측, "1:1 상담 신청" 버튼 좌측에 "원장님의 낙서" 메뉴 추가 → `graffiti.html`로 이동 |
| 목록 페이지 | `graffiti.html` 신규 제작. 브레드크럼, 제목/설명, 검색창(실시간 클라이언트 필터), 전체 건수, 게시글 리스트, 10개씩 페이지네이션 |
| 상세 페이지 | `graffiti-detail.html` 신규 제작. 뱃지, 제목, 작성일/조회수, 본문, 이전글·다음글 이동, 목록 버튼 |
| 게시글 이동 | 이전글 = 목록에서 바로 위(최신 방향), 다음글 = 목록에서 바로 아래(과거 방향). 최신/최초 글 경계에서는 "가장 최신 글입니다" / "가장 마지막 글입니다" 안내 노출 |
| 데이터 | `assets/js/graffiti-data.js`에 임시 목록 데이터 24건을 별도 파일로 분리, 목록/상세 페이지가 공유하여 사용 |

## 3. 기술 구성

- **마크업/스타일**: `index.html`과 동일한 방식(Tailwind CDN + `brand` 컬러, Pretendard 폰트)으로 단일 HTML 파일 2종 제작, 별도 빌드 불필요
- **데이터/렌더링**: 게시글 데이터는 `assets/js/graffiti-data.js`의 `GRAFFITI_POSTS` 배열로 관리하고, 각 페이지는 순수 JS로 정렬·페이징·검색·상세 렌더링을 수행
- **페이지네이션**: 10건 단위, 5페이지 그룹 단위 이동(«, ‹, 숫자, ›, »), 경계에서 버튼 비활성화
- **향후 확장 계획**: `GRAFFITI_POSTS` 배열은 추후 Firebase Firestore 조회 결과로 그대로 교체할 수 있도록 구조화(파일 상단에 TODO 주석으로 명시)했습니다. 현재 리스트/상세 데이터는 임시 목데이터이며, 실 데이터 연동 시 목록/상세 페이지의 렌더링 로직은 그대로 유지한 채 데이터 소스만 교체하면 됩니다.

## 4. 검증

- 로컬 정적 서버(`python3 -m http.server`)로 `index.html` / `graffiti.html` / `graffiti-detail.html`을 구동
- Chrome 브라우저 자동화(claude-in-chrome)로 아래 항목을 직접 클릭·입력하며 확인
  - `index.html` 네비게이션의 "원장님의 낙서" 클릭 → `graffiti.html` 정상 이동
  - 목록 페이지: 전체 24건, 1/2/3페이지 각 10·10·4건 정상 분할, 페이지 버튼 클릭 시 목록 갱신
  - 검색창에 "AI" 입력 → 4건으로 실시간 필터링, 페이지가 1페이지로 리셋되는 것 확인
  - 목록에서 게시글 클릭 → 상세 페이지 이동, 이전글/다음글 항목이 목록 순서와 일치하는지 확인
  - 최신글(id=24)에서 "이전글" 없음 안내, 최초글(id=1) 경계 동작 확인
