### 1-1. `graffiti.html`

### 1-2. `graffiti-new.html` (신규)
- 페이지 진입 즉시 원장 비밀번호(`sungwons`) 인증 모달이 뜨며, **인증을 취소하거나 실패(취소 클릭)하면 자동으로 목록(`graffiti.html`)으로 돌아갑니다.**

- **등록**: 제목·내용을 검증한 뒤, 기존 게시글 중 최대 `id`+1을 새 글 번호로 부여하여 Firestore에 저장(`createPost`)합니다. 저장 성공 시 방금 등록한 글의 상세 페이지로 이동합니다.
- **취소**: 입력 도중 언제든 클릭하면 확인 절차 없이 바로 목록으로 돌아갑니다(작성 중인 내용은 저장되지 않음).
- 저장 실패 시(현재는 config가 임시값이라 항상 실패) 입력한 제목/내용을 **그대로 유지한 채** 오류 메시지만 표시하여, 재시도하거나 취소할 수 있게 했습니다.

### 1-3. `assets/js/firebase-client.js`

### 1-4. 검증 (claude-in-chrome)

- 올바른 비밀번호 입력 → 폼 활성화 확인
- 제목/내용 입력 후 "등록" 클릭 → "등록 중..." 표시 → (임시 config이므로) 약 6초 후 "Firebase 연동이 완료되지 않아 저장할 수 없습니다" 오류 표시, 입력값 보존 확인
- "취소" 버튼 클릭 시 목록으로 즉시 이동 확인

## 2. 왜 지금은 "등록"이 실제로 저장되지 않는가

`assets/js/firebase-config.js`가 아직 **임시(placeholder) 값**이기 때문입니다. 실제 Firebase 프로젝트를 만들고 이 파일의 값을 교체해야 등록·수정·삭제가 실제로 Firestore에 반영됩니다. 이어서 그 절차를 안내합니다.

## 3. "프로덕션 모드"로 Firestore를 구성하기 위해 해야 하는 일 (체크리스트)

1. **Firebase 프로젝트 생성**
   [https://console.firebase.google.com](https://console.firebase.google.com) 접속 → "프로젝트 추가" → 프로젝트 이름 입력(예: `recode-coding`) → Google Analytics는 이 용도에서는 꺼도 무방.

2. **Firestore Database 생성**
   좌측 메뉴 "빌드 > Firestore Database" → "데이터베이스 만들기" 클릭.
   - **위치(리전) 선택**: 한 번 정하면 이후 변경 불가. 국내 서비스라면 `asia-northeast3(서울)` 권장.
   - **모드 선택**: **"프로덕션 모드에서 시작"** 선택 (이미 안내드린 대로, 30일 후 자동 잠기는 테스트 모드보다 안전).

3. **보안 규칙(Rules) 설정 및 게시**
   생성 직후에는 모든 읽기/쓰기가 차단된 상태이므로, "규칙" 탭에서 아래와 같은 규칙을 붙여넣고 **"게시"** 를 눌러야 사이트가 정상 동작합니다.
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /graffiti_posts/{postId} {
         allow read: if true;   // 목록/상세는 누구나 열람 가능
         allow write: if false; // 쓰기는 우선 차단 (아래 4번 참고)
       }
     }
   }
   ```
   > ⚠️ 지금 코드는 클라이언트 JS에서 비밀번호(`sungwons`)만 확인할 뿐, **Firebase 서버(Firestore 규칙) 입장에서는 "누가 원장인지" 알 방법이 없습니다.** 그래서 위 규칙처럼 쓰기를 완전히 열어주면 웹사이트를 거치지 않고도 누구나 Firestore API를 직접 호출해 삭제할 수 있는 위험이 생깁니다. 반대로 위처럼 막아두면, 방금 만든 "등록/수정/삭제" 기능은 비밀번호 인증에는 성공해도 실제 저장은 계속 실패합니다. **아래 4번에서 이 부분을 어떻게 할지 정해야 합니다.**

4. **웹 앱 등록 및 설정값 발급**
   "프로젝트 설정(⚙️) > 일반 > 내 앱" → 웹 아이콘(`</>`)으로 앱 추가 → 앱 이름 입력(예: `recode-coding-web`) → 발급되는 `firebaseConfig` 객체(apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId) 확인.

5. **발급받은 값을 `assets/js/firebase-config.js`에 반영**
   지금 파일에 있는 `TEMP_*` 값들을 4번에서 받은 실제 값으로 교체.

## 4. 쓰기 보안, 두 가지 선택지 (결정 필요)

| | A안: 지금처럼 클라이언트 비밀번호만 사용 | B안: Firebase Authentication 도입(권장) |
| --- | --- | --- |
| 추가 작업 | 없음 (현재 코드 그대로) | 원장 전용 로그인 화면/로직 추가, 규칙에 `request.auth` 조건 추가 |
| 결과 | Firestore 규칙에서 쓰기를 열어야 하므로 사이트를 거치지 않고도 API로 직접 쓰기 가능(위험) | 로그인한 원장만 실제로 쓰기 가능, 웹사이트로 등록·수정·삭제가 안전하게 동작 |
| "새로운 낙서" 기능 | 쓰기를 열어야만 실제로 작동(보안 트레이드오프 감수) | 로그인 붙인 뒤에만 실제로 작동 |

**권장(B안)**: 지금 만든 등록/수정/삭제 기능을 실제로 쓰시려면, Firebase Authentication으로 원장 전용 로그인을 붙이고 규칙을 `allow write: if request.auth != null;` 형태로 바꾸는 것을 권장드립니다. 이 부분은 제가 이어서 코드로 구현해 드릴 수 있습니다 (로그인 폼 + Firebase Auth 연동 + 기존 비밀번호 모달을 로그인으로 교체).
