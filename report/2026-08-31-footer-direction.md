## 1. 왜 1차 시안이 마음을 움직이지 못했나

사용자 반응: *"디자인이 부족한지, 내가 생각하는 아이디어가 부족한지.. 마음이 움직이질 않네"*

**제 쪽 문제였다.** A~D를 다시 보면 넷 다 같은 아이디어의 판본이다.

| 시안 | 실제로 다른 것 |
| --- | --- |
| A 다크 대비 | 톤(어둡게) |
| B 라이트 정돈 | 톤(그대로) |
| C CTA 결합 | CTA를 위에 얹음 |
| D 미니멀 | 높이를 줄임 |

전부 **"링크를 칼럼으로 늘어놓는 푸터"** 라는 하나의 발상 위에 있었다. 톤과 밀도만 다른 넷은 선택지가 아니다.

근본 원인은 순서였다 — **"이 푸터가 무엇을 해야 하는가"를 묻지 않고 "무엇을 넣을 수 있나"(링크·CTA·사업자 정보)부터 뒤졌다.** 그러니 나온 것이 전부 목록의 변주였다.

## 2. 다시 제시한 축 5가지

발상 자체가 다른 것들로 다시 냈다.

| 축 | 푸터가 무엇이 되는가 |
| --- | --- |
| 터미널 | 셸 세션 — 링크가 명령의 출력 |
| **살아 있는 푸터** | 브랜드 질감 — 정렬 시각화가 상시 동작 |
| 원장의 사인 | 맺음말 — 최신 낙서 글과 서명 |
| 커리큘럼 지도 | 훈련 경로의 모양을 마지막에 한 번 더 |
| 아예 비우기 | 상담 한 줄과 저작권만 |

함께 전한 판단 하나 — **푸터에 마음이 안 움직이는 것 자체가 정상일 수 있다.** 푸터는 원래 조용한 자리이고, Unity·Agent AI 상세 8장이 비어 있는 지금 에너지를 쓸 곳은 그쪽일 수도 있다고 밝혔다.

## 3. 제작한 두 안

사용자가 터미널·살아 있는 푸터를 골라 목업으로 그렸다.

**터미널 푸터** — 푸터가 셸 세션이 된다. `recode.ai.kr ~ %` 프롬프트 아래로 `ls courses/` · `ls services/` · `open company/`의 출력으로 링크가 놓이고, 상담 신청은 `recode apply --1on1`이라는 실행 가능한 명령으로 제시된다. 마지막 줄에 깜빡이는 커서. `JetBrains Mono`와 `<>` 로고가 이미 디자인 토큰에 있어 새 언어를 들여오는 게 아니라 가진 것을 밀어붙이는 안. **채택하지 않음** — 취향을 크게 타고, 학부모에게는 읽히지 않을 수 있다.

**살아 있는 푸터 — 채택.** 푸터 바닥에서 정렬이 계속 돌아간다. 46개 막대가 회색에서 **왼쪽부터** 브랜드 그린으로 바뀌며 훑고 지나가고, 호박색 세로선이 그 경계를 따라간다. 16초 주기로 눈에 거슬리지 않게 맞췄고 `prefers-reduced-motion`이면 정지한다. 카피는 `// still sorting.` 한 줄뿐 — 그림을 말로 설명하면 힘이 빠지기 때문.

논지는 이것이다: **정렬·탐색·자료구조 시각화 14종은 다른 학원이 못 만드는 이 사이트만의 자산이고, 그것을 브랜드 질감으로 쓴다.**

구현 중 방향 버그 하나를 잡았다 — 막대 위상을 `-i * 0.34s`로 주면 초록이 **오른쪽부터** 번진다(인덱스가 클수록 위상이 앞서므로). `-(COUNT-1-i) * 0.34s`로 뒤집어 왼쪽부터 정렬되도록 맞췄다.

## 4. 남은 결정 — 내용

**방향만 정해졌고 내용은 미정이다.** 사용자가 다시 고민하기로 했다.

- 어떤 링크를 어떤 묶음으로 둘지
- 카피를 어떻게 쓸지 (목업의 `// still sorting.`도 임시)
- 사업자 정보(상호·대표·사업자등록번호·주소) 표기 여부
- 죽은 링크 2개(FAQ·문의)의 목적지

**목업의 링크 구성과 문구는 배치를 보기 위한 임시안이므로 그대로 옮기지 말 것** — 이 주의사항을 `CLAUDE.md`와 `DEV_PLAN.md` Phase 4 양쪽에 남겼다.

## 5. 채택안 핵심 코드 (저장소 보존분)

목업은 세션 임시 폴더와 Artifact에만 있어 둘 다 사라지면 그림이 남지 않는다. **구현에 실제로 필요한 부분만 여기 옮겨 둔다** — 이것만 있으면 Artifact 없이도 재현된다. 아래는 목업(`Living.dc.html`)의 인라인 스타일을 그대로 옮긴 것이므로, `partials/footer.html`에 넣을 때는 사이트 관례대로 Tailwind 유틸리티로 바꿔 쓰고 애니메이션 부분만 `<style>`로 남긴다.

막대는 46개, 높이는 고정이고 **색만** 왼쪽에서 오른쪽으로 정렬되어 간다. 배치는 푸터 바닥에 `position:absolute`로 깔고(`height:132px`, `opacity:.5`, `gap:3px`) 본문은 그 위에 `position:relative`로 얹는다.

```css
.bar { animation: sweep 16s linear infinite; will-change: background-color; }
@keyframes sweep {
  0%,  46% { background-color: #cbd5e1; }  /* 대기(회색) */
  50%, 94% { background-color: #18b476; }  /* 정렬 완료(브랜드 그린) */
  98%, 100% { background-color: #cbd5e1; }
}
/* 비교 중인 지점 — 초록 경계와 같은 속도로 따라간다 */
.scan { animation: scan 16s linear infinite; }  /* width:2px; background:#f59e0b */
@keyframes scan {
  0%   { left: 0%;   opacity: 0; }
  6%   { opacity: 1; }
  92%  { opacity: 1; }
  100% { left: 100%; opacity: 0; }
}
@media (prefers-reduced-motion: reduce) {
  .bar, .scan { animation: none; }
  .scan { opacity: 0; }
}
```

막대 높이와 위상은 정적 사이트이므로 **빌드 때 인라인 style로 박아 두면 런타임 JS가 필요 없다**(푸터가 30장에 들어가므로 스크립트를 늘리지 않는 편이 낫다). 생성 규칙:

```js
const COUNT = 46;
let seed = 7;
for (let i = 0; i < COUNT; i++) {
  seed = (seed * 1103515245 + 12345) % 2147483648;   // 재현 가능한 난수
  const h = 18 + (seed % 1000) / 1000 * 96;          // 18~114px
  // flex:1 1 0; min-width:0; border-radius:2px 2px 0 0; background:#cbd5e1;
  // animation-delay 는 부호와 순서에 주의 — 아래가 "왼쪽부터" 맞는 식이다
  const delay = -(COUNT - 1 - i) * 0.34;             // 초 단위
}
```

`animation-delay`를 `-i * 0.34s`로 주면 초록이 **오른쪽부터** 번진다(위 §3 버그). 반드시 `-(COUNT-1-i)`로 뒤집을 것.
