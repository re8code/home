# 작업 지시서 — 프로젝트 매니페스트 생성

각 프로젝트 폴더에서 Claude Code를 열고 이 문서를 붙여넣어 실행한다.
목적은 이 레포에 흩어진 md 문서들을 읽어 기계가 읽을 수 있는 `.project-meta.json` 하나를 만드는 것이다.

---

## 작업 범위

**이 폴더 안에서만 작업한다.** 다른 프로젝트 폴더나 상위 디렉터리는 건드리지 않는다.

코드는 수정하지 않는다. 생성하는 파일은 `.project-meta.json` 하나뿐이다.

---

## 절차

### 1단계 — 문서 수집

레포 루트와 `docs/`, `.github/` 아래의 md 파일을 모두 읽는다. 스택, 인프라, 외부 서비스, 계정, 비용, 배포에 관한 서술을 찾는다.

`package.json`, `docker-compose.yml`, `.env.example`, `vercel.json` 등 설정 파일도 읽어 참고한다. 다만 이것들은 **참고용**이며 결과 JSON에 그대로 옮기지 않는다 (3단계 참조).

### 2단계 — JSON 생성

아래 스키마에 맞춰 레포 루트에 `.project-meta.json`을 만든다.

### 3단계 — 보고

작업 후 다음을 사람에게 보고한다.

- `null`로 남긴 필드 목록과 그 이유
- 문서에서 서로 모순되는 정보를 발견한 경우 그 내용
- 문서에 언급은 없지만 설정 파일에서 발견된 외부 서비스 (누락 가능성)

---

## 스키마

```json
{
  "meta_version": 1,
  "updated_at": "2026-09-03",

  "project": {
    "name": "acme-dashboard",
    "display_name": "Acme 관리자 대시보드",
    "status": "production",
    "repo": "github.com/me/acme-dashboard",
    "note": "사내 운영팀용 대시보드"
  },

  "stack": [
    { "name": "Next.js", "version": "15", "role": "frontend", "note": "App Router" },
    { "name": "PostgreSQL", "version": "16", "role": "database", "note": "Supabase 관리형" }
  ],

  "services": [
    {
      "provider": "vercel",
      "display_name": "Vercel",
      "category": "hosting",
      "plan": "Pro",
      "cost": { "amount": 20, "currency": "USD", "cycle": "monthly" },
      "seats": 1,
      "owner_email": "me@example.com",
      "account_ref": "1password://vercel-team",
      "billing_ref": "1password://amex-8842",
      "recovery_ref": "1password://vercel-2fa",
      "renewal": "2026-10-01",
      "criticality": "high",
      "free_tier_limit": null,
      "note": null
    }
  ]
}
```

---

## 필드 규칙

### 값이 고정된 필드 (반드시 아래 목록 중 하나)

이 필드들은 여러 프로젝트를 가로질러 묶는 축이다. 표기가 하나만 어긋나면 집계가 갈라진다.

| 필드 | 허용값 |
|---|---|
| `project.status` | `production` / `staging` / `paused` / `archived` |
| `services[].category` | `hosting` / `database` / `auth` / `monitoring` / `analytics` / `email` / `storage` / `cdn` / `ai-api` / `domain` / `ci` / `payment` / `other` |
| `services[].cost.cycle` | `monthly` / `yearly` / `usage` / `free` |
| `services[].cost.currency` | `USD` / `KRW` (ISO 4217 대문자) |
| `services[].criticality` | `high` / `medium` / `low` |
| `stack[].role` | `frontend` / `backend` / `database` / `infra` / `mobile` / `tooling` |

### `provider` — 소문자 슬러그

공백과 대문자를 쓰지 않는다. `vercel`, `supabase`, `sentry`, `cloudflare`, `aws-s3`, `openai`.
사람이 볼 이름은 `display_name`에 따로 넣는다.

동일 서비스를 프로젝트마다 다르게 적으면 중복 탐지가 실패한다. 확신이 없으면 서비스의 도메인 앞부분을 슬러그로 쓴다.

### `criticality` 판단 기준

- `high` — 없으면 서비스가 죽는다 (호스팅, DB, 인증)
- `medium` — 없으면 기능이 일부 손실된다 (모니터링, 메일)
- `low` — 없어도 운영에 지장 없다 (분석, 부가 도구)

### `cost`

`cycle`이 `yearly`면 `amount`에 **연간 금액을 그대로** 넣는다. 월 환산은 취합 도구가 한다.
사용량 과금이면 `cycle`을 `usage`로 하고 `amount`에 최근 월 실제 청구액을, `note`에 근거를 적는다.
무료면 `cycle`을 `free`, `amount`를 `0`으로 하고 `free_tier_limit`에 한도를 적는다.

## 절대 규칙

### 추측하지 않는다

문서에 없는 값은 **반드시 `null`**로 둔다. 그럴듯한 기본값을 채워 넣지 않는다.

특히 **비용은 절대 추정하지 않는다.** "Vercel Pro는 보통 월 20달러"라는 일반 지식으로 채우면, 사람은 그게 실제 청구액인지 추측값인지 구분할 수 없게 되고 전체 합계가 조용히 틀어진다. 문서에 금액이 없으면 `amount`를 `null`로 두고 보고 단계에서 알린다.

`updated_at`은 오늘 날짜를 넣되, 사람이 검토하기 전이므로 보고 시 "미검증 상태"임을 명시한다.

### 자격증명을 넣지 않는다

이 파일은 커밋될 가능성이 높다. 다음은 어떤 경우에도 JSON에 넣지 않는다.

- 비밀번호, API 키, 토큰, 시크릿, 접속 문자열
- `.env` 파일의 실제 값

`*_ref` 필드에는 **위치를 가리키는 참조만** 넣는다.

- `1password://항목이름`
- `env://VARIABLE_NAME`
- `bitwarden://항목이름`

`owner_email`은 로그인 계정 식별용이므로 실제 이메일을 넣어도 된다. 비밀번호가 아니다.

작업 중 문서나 설정 파일에서 실제 키나 비밀번호를 발견하면, JSON에 넣지 말고 **보고 단계에서 별도로 경고한다.**

### 코드에서 알 수 있는 것은 넣지 않는다

`package.json`의 의존성 목록, lock 파일의 정확한 버전, 개별 라이브러리 목록은 매니페스트에 옮기지 않는다. 취합 도구가 직접 감지한다.

`stack` 배열에는 **선언한 의도**만 적는다. 즉 "무엇을 쓰기로 정했는가"다. 관리형 DB, 선택한 프레임워크, 아키텍처 결정처럼 코드만 봐서는 알 수 없거나 의도가 드러나야 하는 것들이다.

이 구분이 중요한 이유는, 취합 도구가 **선언된 스택과 실제 감지된 의존성을 대조**해서 기록이 낡은 프로젝트를 찾아내기 때문이다. 매니페스트가 코드를 복사한 것이면 이 대조가 무의미해진다.

손으로 유지하는 필드가 적을수록 이 시스템은 오래 간다.

---

## 마무리

`.gitignore`를 확인한다. `.project-meta.json`에는 계정 이메일과 갱신일이 들어가므로, 레포가 공개 저장소라면 반드시 `.gitignore`에 추가하고 그 사실을 보고한다. 비공개 저장소라면 커밋하는 편이 변경 이력이 남아 유리하다. 판단이 서지 않으면 사람에게 묻는다.
