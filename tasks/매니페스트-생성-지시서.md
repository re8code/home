# 작업 지시서 — 프로젝트 매니페스트 생성

각 프로젝트 폴더에서 Claude Code를 열고 이 문서를 붙여넣어 실행한다.
목적은 이 레포에 흩어진 md 문서들을 읽어 기계가 읽을 수 있는 `.project-meta.json` 하나를 만드는 것이다.

이 문서 하나로 완결된다. 다른 저장소를 참조하지 않아도 된다.

---

## 작업 범위

**이 폴더 안에서만 작업한다.** 다른 프로젝트 폴더나 상위 디렉터리는 건드리지 않는다.

코드는 수정하지 않는다. 생성하는 파일은 `.project-meta.json` 하나뿐이다.

---

## 절차

### 1단계 — 문서 수집

레포 루트와 `docs/`, `.github/` 아래의 md 파일을 모두 읽는다. 스택, 인프라, 외부 서비스, 계정, 비용, 배포에 관한 서술을 찾는다.

`package.json`, `docker-compose.yml`, `.env.example`, `vercel.json` 등 설정 파일도 읽어 참고한다. 다만 이것들은 **참고용**이며 결과 JSON에 그대로 옮기지 않는다 (아래 "코드에서 알 수 있는 것은 넣지 않는다" 참조).

### 2단계 — JSON 생성

아래 스키마에 맞춰 레포 루트에 `.project-meta.json`을 만든다.

### 3단계 — 자가 검증

파일을 다 쓴 뒤 **"완료 전 자가 검증"** 절의 체크리스트를 직접 돌린다. 여기서 걸리는 것을 남겨두면 취합 도구에서 경고로 올라온다.

### 4단계 — 보고

작업 후 다음을 사람에게 보고한다.

1. **★ 계정 확인이 필요한 서비스 목록** — 계정이 존재하는데 문서에서 `owner_email`을 찾지 못한 것.
   추측해서 채우지 말고, **"이 서비스는 어느 계정인가"를 사람에게 물어 목록으로 제시한다.**
   이것이 보고에서 가장 중요한 항목이다
2. `null`로 남긴 나머지 필드와 그 이유
3. 문서에서 서로 모순되는 정보를 발견한 경우 그 내용
4. 문서에 언급은 없지만 설정 파일에서 발견된 외부 서비스 (누락 가능성)
5. `.gitignore` 판단 결과 (마지막 절 참조)

## 스키마

```json
{
  "meta_version": 1,
  "updated_at": "2026-09-04",

  "project": {
    "name": "acme-dashboard",
    "display_name": "Acme 관리자 대시보드",
    "status": "production",
    "repo": "github.com/me/acme-dashboard",
    "note": "사내 운영팀용 대시보드"
  },

  "stack": [
    { "name": "Next.js", "version": "15", "role": "frontend", "note": "App Router" },
    { "name": "PostgreSQL", "version": "16", "role": "database", "note": "Supabase 관리형" }
  ],

  "services": [
    {
      "provider": "supabase",
      "display_name": "Supabase",
      "category": "database",
      "plan": "Free",
      "cost": { "amount": 0, "currency": null, "cycle": "free" },
      "seats": null,
      "owner_email": "me@example.com",
      "account_ref": "1password://supabase",
      "billing_ref": null,
      "recovery_ref": "1password://supabase-2fa",
      "renewal": null,
      "criticality": "high",
      "free_tier_limit": "Free 한도 초과 시 차단(과금 없음). 7일 미활동 시 자동 일시정지",
      "note": null
    }
  ]
}
```

## 필드 규칙

### 값이 고정된 필드 (반드시 아래 목록 중 하나)

이 필드들은 여러 프로젝트를 가로질러 묶는 축이다. 표기가 하나만 어긋나면 집계가 갈라진다.
**목록에 없는 값을 창작하지 않는다.** 애매하면 `other`(category) 또는 `tooling`(role)을 쓴다.

| 필드 | 허용값 |
|---|---|
| `project.status` | `production` / `staging` / `development` / `paused` / `archived` |
| `services[].category` | `domain` / `hosting` / `database` / `email` / `cdn` / `ci` / `auth` / `storage` / `analytics` / `payment` / `ai` / `monitoring` / `other` |
| `services[].cost.cycle` | `monthly` / `yearly` / `free` / `onetime` / `usage` / `null` |
| `services[].cost.currency` | `KRW` / `USD` / `null` |
| `services[].criticality` | `high` / `medium` / `low` |
| `stack[].role` | `frontend` / `backend` / `database` / `infra` / `tooling` |

**자주 나는 실수 두 가지.**

- **AI API는 `ai`다. `ai-api`가 아니다.** 서비스 이름에 "API"가 들어가면 손이 먼저 `ai-api`를
  친다. Anthropic·OpenAI 모두 `ai`로 적는다
- **`role`에 `mobile`은 없다.** 모바일 관련은 `frontend`로 적는다

### ★ `owner_email` — 계정이 있는 서비스는 반드시 채운다

**이 값 하나로 "계정별 조회"와 "비상시 복구 경로"가 만들어진다.** 비어 있으면 그 서비스를 잃었을 때
어느 계정으로 복구하는지 알 방법이 없다. 취합 도구는 이것을 `[medium] 계정 미기입` 경고로 띄운다.

**이름이 `account_ref`·`billing_ref`·`recovery_ref`와 비슷하지만 성격이 정반대다.**
`*_ref`는 자격증명 위치를 가리키는 참조라 비워두는 편이 낫지만, `owner_email`은
**로그인 계정 식별자이고 반드시 채우는 값**이다. 비밀번호가 아니다.

`null`로 두어도 되는 것은 **계정이라는 개념 자체가 없는 서비스**뿐이다.

- `category: cdn` — Tailwind Play CDN, jsDelivr, unpkg, gstatic 처럼 URL 로만 쓰는 것
- 로그인 없이 공개 엔드포인트만 쓰는 것

**그 외에는 전부 채운다.** 특히 다음은 계정 없이 존재할 수 없다 —
호스팅 · DB · 도메인 등록기관 · GitHub · 클라우드 · AI API · 메일 · 결제.

문서에서 찾지 못했다면 **`null`로 묻어두지 말고 4단계 보고의 1번 항목에 올려 사람에게 묻는다.**
이것이 "추측하지 않는다" 규칙의 유일한 예외 처리 방식이다 — 추측하지도 않고, 조용히 비우지도 않는다.

### `provider` — 소문자 슬러그

공백과 대문자를 쓰지 않는다. `vercel`, `supabase`, `sentry`, `cloudflare`, `aws-s3`, `openai`.
사람이 볼 이름은 `display_name`에 따로 넣는다.

동일 서비스를 프로젝트마다 다르게 적으면 중복 탐지가 실패한다. 확신이 없으면 서비스의 도메인 앞부분을 슬러그로 쓴다.

### `criticality` 판단 기준

**문서의 서술이 아니라 "없으면 서비스가 죽는가"로 판단한다.**

- `high` — 없으면 서비스가 죽는다 (호스팅, DB, 인증, 도메인)
- `medium` — 없으면 기능이 일부 손실된다 (모니터링, 메일)
- `low` — 없어도 운영에 지장 없다 (분석, 부가 도구)

폴백이 없는 CDN 은 `high` 다. 죽으면 전 페이지 스타일이 즉시 깨지기 때문이다.

### `cost` — 이 생태계는 금액을 적지 않는다

**요금제는 수시로 바뀌므로 각 서비스 콘솔의 값이 정본이다.** 매니페스트에는 금액 대신
*"무엇이 언제 돈이 되기 시작하는가"* 를 남긴다. `amount: null`이어도 도구는 깨지지 않는다.

| 상황 | 표기 |
|---|---|
| 무료 | `{ "amount": 0, "currency": null, "cycle": "free" }` |
| 종량 과금 (Cloud Run·Anthropic API 등) | `{ "amount": null, "currency": null, "cycle": "usage" }` |
| 확정 지출이 문서에 적혀 있음 | `amount`에 그대로, `cycle`은 `monthly`/`yearly` (연간이면 연 금액 그대로. 월 환산은 도구가 한다) |
| 일회성 | `cycle: "onetime"` |
| 모름 | 전부 `null` |

**종량 과금의 `amount`는 `null`로 둔다.** 미리 적을 수 있는 값이 아니다. 최근 청구액을 적으면
다음 달에 곧바로 거짓이 된다. 대신 `note`에 **지출 상한을 걸어 두었는지**를 적는다 —
이 축에서 가장 쓸모 있는 정보다.

### ★ `free_tier_limit` — 이 생태계에서 실제로 값을 내는 필드

금액보다 *"초과하면 차단인가 과금인가"* 가 중요하다. 무료 서비스라면 이것을 반드시 채운다.

- Firebase Spark → 한도 초과 시 **차단**, 자동 과금 없음
- Cloud Run → 결제 계정이 연결돼 있으면 한도 초과분이 **조용히 청구됨**
- Supabase Free → 7일 미활동 시 자동 일시정지

**"차단"과 "조용히 청구됨"의 차이가 이 필드의 존재 이유다.** 문서에 한도 수치가 없으면
거동만이라도 적는다.

## 절대 규칙

### 추측하지 않는다

문서에 없는 값은 **`null`**로 둔다. 그럴듯한 기본값을 채워 넣지 않는다.

특히 **비용은 절대 추정하지 않는다.** "Vercel Pro는 보통 월 20달러"라는 일반 지식으로 채우면,
사람은 그게 실제 청구액인지 추측값인지 구분할 수 없게 되고 전체 합계가 조용히 틀어진다.

**단, `owner_email`은 다르게 처리한다.** 계정이 존재하는 서비스인데 문서에 계정 주소가 없다면,
`null`로 두고 끝내지 말고 **보고 단계에서 사람에게 물어 목록으로 제시한다.** 추측은 하지 않되
누락을 조용히 넘기지도 않는다. 비어 있는 채로 두면 아무도 그것이 빠졌다는 사실을 모른다.

`updated_at`은 오늘 날짜를 넣되, 사람이 검토하기 전이므로 보고 시 "미검증 상태"임을 명시한다.

### 자격증명을 넣지 않는다

이 파일은 커밋될 가능성이 높다. 다음은 어떤 경우에도 JSON에 넣지 않는다.

- 비밀번호, API 키, 토큰, 시크릿, 접속 문자열
- `.env` 파일의 실제 값

`*_ref` 필드에는 **위치를 가리키는 참조만** 넣는다.

- `1password://항목이름`
- `env://VARIABLE_NAME`
- `bitwarden://항목이름`

작업 중 문서나 설정 파일에서 실제 키나 비밀번호를 발견하면, JSON에 넣지 말고 **보고 단계에서 별도로 경고한다.**

### 코드에서 알 수 있는 것은 넣지 않는다

`package.json`의 의존성 목록, lock 파일의 정확한 버전, 개별 라이브러리 목록은 매니페스트에 옮기지 않는다. 취합 도구가 직접 감지한다.

`stack` 배열에는 **선언한 의도**만 적는다. 즉 "무엇을 쓰기로 정했는가"다. 관리형 DB, 선택한 프레임워크, 아키텍처 결정처럼 코드만 봐서는 알 수 없거나 의도가 드러나야 하는 것들이다.

이 구분이 중요한 이유는, 취합 도구가 **선언된 스택과 실제 감지된 의존성을 대조**해서 기록이 낡은 프로젝트를 찾아내기 때문이다. 매니페스트가 코드를 복사한 것이면 이 대조가 무의미해진다.

손으로 유지하는 필드가 적을수록 이 시스템은 오래 간다.

## 완료 전 자가 검증

파일을 저장하기 전에 아래를 직접 확인한다. 여기서 걸리는 것은 전부 취합 도구에서 경고로 올라온다.

- [ ] **`owner_email`이 비어 있는 서비스가 있는가?**
      → `category: cdn` 이거나 로그인이 없는 서비스인가? 아니면 보고 1번 항목에 올렸는가?
- [ ] `category` 값이 전부 허용 목록 안에 있는가? (`ai-api` 를 쓰지 않았는가?)
- [ ] `role` 값이 전부 허용 목록 안에 있는가? (`mobile` 을 쓰지 않았는가?)
- [ ] `provider`가 전부 소문자 슬러그인가? 같은 서비스를 다른 프로젝트와 다르게 적지 않았는가?
- [ ] 무료 서비스에 `free_tier_limit`을 채웠는가? "차단인가 과금인가"가 드러나는가?
- [ ] `cycle: "usage"` 인 항목의 `amount`가 `null` 인가?
- [ ] `criticality`를 문서 서술이 아니라 "없으면 죽는가"로 판단했는가?
- [ ] JSON이 파싱되는가? (`node -e "JSON.parse(require('fs').readFileSync('.project-meta.json','utf8'))"`)

## 마무리 — `.gitignore` 판단

**기본은 커밋이다.** 매니페스트를 `.gitignore`에 넣으면 **다른 장비에서 이 프로젝트가 집계 대상에서
통째로 빠진다.** 매니페스트가 없는 폴더는 추적 대상이 아니기 때문이다. 변경 이력도 남지 않아
"언제 무엇이 왜 바뀌었는지" 확인할 수 없게 된다.

| 저장소 | 처리 |
|---|---|
| **비공개** | **커밋한다.** `.gitignore`에 넣지 않는다 |
| **공개** | `.gitignore`에 추가한다. 계정 이메일이 공개되기 때문이다 |

공개 저장소라 제외했다면 그 사실을 **반드시 보고한다.** 그 프로젝트는 장비를 옮길 때마다
매니페스트를 손으로 복사해야 하고, 그러지 않으면 조용히 집계에서 빠진다.

판단이 서지 않으면 사람에게 묻는다.
