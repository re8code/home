# 요구사항 누락 점검 — 프로젝트 관리 시스템

- 일시: 2026-10-18 (회의 후반)
- 대상: [`2026-10-18-project-system-meeting.md`](2026-10-18-project-system-meeting.md) §4의 요구사항 R1~R54
- 상태: **전부 미결** — 결정되면 회의록(또는 옮겨 간 새 저장소의 문서)에 반영하고 여기서는 지운다.
- 이 파일도 `_handoff/`의 임시 보관본이다. 프로젝트 저장소가 생기면 회의록과 함께 옮긴다.

R1~R54를 프로젝트 한 건의 일생·사람 한 명의 일생에 대어 비어 있는 곳을 찾은 결과. **전부 미결**이며, 우선 논의 대상은 **G2(배포 환경)와 G7(개인정보)** — G2는 1차 설계에 바로 영향, G7은 첫 훈련생을 받기 전에 약관에 들어가야 한다.

**A. 1차에서 빠진 것**
- **G1. 온보딩** — GitHub 계정 연결, Claude Code 설치·Pro 구독 확인, **대화 기록 훅 동작 점검**(처음부터 안 돌면 기록 누락이 전부 위반으로 찍힌다). 첫 프로젝트 전 틀 연습 과제를 둘지.
- **G2. 훈련 프로젝트의 배포 환경·외부 계정** — 평가 A에 "배포", Phase 심사에 "미리보기 배포 주소"가 있는데 어디에·누구 계정으로·비용은 누가 내는지 없다. 훈련용 DB·외부 API 키도 같다. 에이전시 공용 실습 환경 vs 훈련생이 무료 플랜으로 직접 — 비밀값 전달(R38) 방식도 이에 따라 달라진다.
- **G3. 같은 클론 과제의 부정행위** — 과제 반복 배정(R11)으로 앞 기수 결과물 복사 위험. 이전 결과물 열람 제한·유사도 감지. 미결 "동료 간 열람 범위"와 직결.
- **G4. 중도 이탈·방치** — 중단 처리, 기록 보존, 저장소 처리. 수강권 만료(R17)와 맞물림.
- **G5. Phase 기한 초과** — 연장 요청을 변경 요청으로 받을지, 자동 정체 신호, 평가 F 반영 방식.
- **G6. 동시 진행 개수** — 한 번에 하나로 제한하면 관리가 단순.

**B. 정책·법 (시스템 이전에)**
- **G7. 개인정보·보존 기간** — "기록은 지우지 않는다"(R2)와 개인정보 보호법상 삭제 요구·보존 기간의 충돌. 대화 기록에 개인적 내용이 섞일 수 있음. 동의 범위·보존 기간·탈퇴 시 삭제/익명화 보존 범위를 약관에.
- **G8. 평가 이의 제기** — 평가 공개(R42)에 따른 경로.
- **G9. 제재** — 비밀값 유출·과제 표절·고객 자료 반출 시 처리(경고·프로젝트 중단·등급 조치).

**C. 에이전시 쪽**
- **G10. 에이전시 내부 역할** — 지금 "에이전시" = 사실상 원장 1인. 심사를 나눠 맡을 사람(조교·나중의 에이전트)을 위해 관리자/리뷰어 역할을 처음부터 구분.
- **G11. 심사 대기열** — Phase PR 대기 목록·대기 일수. 리뷰 지연으로 훈련생이 멈추면 F가 억울하게 깎이지 않도록.
- **G12. 템플릿 버전** — 프로젝트에 템플릿 버전 기록, 진행 중 프로젝트의 갱신 방법.
- **G13. 감사 기록** — 권한 변경·평가 수정·분할선 조정의 행위자·시각. G8의 근거.

**D. 2차(랜서)에서 빠진 것**
- 고객 검수·인수 절차, 납품 후 하자 보수 책임, 고객 계정(무엇을 보는지 — 미결 "고객에게 보드 공개"와 연결).
