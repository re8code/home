# 인수인계 — 프로젝트 관리 시스템 (훈련생 ~ 에이전트)

> 2026-10-18 `home` 저장소 세션에서 진행한 회의의 인계 문서. 회의가 `home`에서 열린 이유는 관련 맥락(대문 재편 D6, 형제 저장소 문서)이 이 세션에 가장 많았기 때문이고, **실제 작업은 새 저장소·새 세션에서 이어간다.**
> 이 폴더(`_handoff/`)는 임시 보관소다. `_` 접두사라 GitHub Pages 배포에서 제외된다.

## 1. 새 세션에서 할 일 (순서대로)

0. **GitHub Organization이 먼저** — `mission`은 개인 계정 `re8code`가 아니라 조직 안에 만든다(조직 이름 후보 `recode-ai`, 소유자 `re8code` + 보조 1명 — `home` ADR D7). 조직은 사용자가 웹에서 직접 만든다.
1. **새 저장소 생성** — `~/recode-ai/mission` (서비스명·저장소명 **`mission`** 확정, 2026-10-18 — 007 은유: 프로젝트 = 임무, 훈련생은 "훈련 임무". 주소는 `mission.recode.ai.kr` 예정). 형제 저장소와 같은 관례로 `dev` 브랜치, `vX.XX` 커밋(v0.01부터).
2. **이 폴더의 파일 3개를 새 저장소로 복사** — 권장 위치: `report/2026-10-18-project-system-meeting.md`, `report/2026-10-18-requirements-gaps.md`, 이 README는 복사하지 않아도 된다.
3. **새 세션의 첫 메시지** 예시:
   > `report/2026-10-18-project-system-meeting.md`와 `report/2026-10-18-requirements-gaps.md`를 읽고 시작하자. `home` 세션에서 한 회의의 연속이다. 형제 저장소(`../agency`·`../recode-db`·`../recodemate`)는 읽기만 한다.
4. **표준 문서 골격 작성** — 형제 저장소와 같은 `CLAUDE.md`(제1원칙 7개 문서·커밋 규칙·장비 간 연속성·`report/` 규칙) + `docs/` 6개. 회의록 §1~§4가 `PRD.md`의 출발점, §7이 `DEV_PLAN.md`의 Phase 골격이다. 사용자 확인 없이 PRD를 확정본처럼 채우지 않는다 — 회의록에 **미결**로 남은 것은 미결로 옮긴다.
5. **`home` 쪽 정리는 나중에 `home` 세션에서** — 옮긴 것이 확인되면 `home`에서 `_handoff/`를 삭제하고 `docs/DEVLOG.md`에 한 줄 남긴다. 새 저장소 세션에서 `home`을 수정하지 않는다(변경은 그 저장소의 세션에서 — `recode-db` CLAUDE.md "세션 운영 원칙"과 같은 방식).

## 3. 한눈에 보는 결론

- **하나의 시스템**: 훈련생 ~ 에이전트를 한 시스템에서. 승급은 `core`의 등급 값 변경(이관·내보내기 없음).
- **틀 = 원장의 문서 체계**를 표준 템플릿으로 강제. **분할선**(학생이 소유하는 문서)이 등급에 따라 내려간다: 훈련생 = task 분해 + 실행 → … → 에이전트 = 전부.
- **훈련생 = 훈련 프로젝트만**(실전 클론·에이전시 과제·본인 기획). **졸업 과제 = 실전 클론**, 관문 심사 근거.
- **바이브 코딩 전제** — Claude Code 강제(Pro 본인 부담), 대화 기록 훅. 평가는 "AI가 짠 것을 책임지고 내놓을 수 있는가": A 결과물 · B 지시력 · C 검증력 · D 이해력(졸업 과제 구술만) · E 통제력 · F 소통·자기 관리, 눈금 4단계, 최저 항목이 판정, 훈련생에게 공개.
- **자동화는 기록에, 생각은 사람에게** / **무엇을 남기는가만 고정, 어떻게 일하는가는 자유** / **막는 것은 사고만, 나머지는 기록**.
- **1차는 돈도 AI 스태프도 없다** — 수업료는 recodemate 수강권(연동 없음), AI 스태프는 보류 아이디어.
